# PROJECT_STATUS

Source of truth for project progress. Update after each completed step. Last updated: 2026-10-02 (Phase 6: Add MSSQL AG and failover cluster to Inventory passing).

## 1. Project goal

Build a QA automation project for the **NAKIVO Backup & Replication** web UI (Director), with an AI-assisted workflow. The folders `knowledge`, `standards`, `templates`, `examples` and `workspace` are reserved for that workflow. `templates` and `examples` are currently empty (`.gitkeep` only), `standards` holds the Phase 4 automation standards and decision register (section 5), `workspace` holds the Phase 3 and later derived material; `knowledge` holds the governance foundation and the ingested knowledge documents (see section 3).

## 6. Important decisions already made

- Playwright + TypeScript. Chromium is the only browser installed.
- `ignoreHTTPSErrors: true` and a fixed `baseURL` are set in the config. Tests use relative paths such as `/c/login`.
- The UI is Ext JS. **Never use generated `ext-gen*` or `simpleIcon-*` ids.** Prefer:
  - Username: `getByPlaceholder('Username')`
  - Password: `getByPlaceholder('Password')`
  - Login button: `getByRole('button', { name: 'LOG IN' })`
  - Authenticated marker: `getByTitle('Logout')`
- The page has no `data-testid` on the login form. The only ones found on the overview page belong to the Events table.
- Credentials come only from `.env`, loaded in the test file. The config reads no environment variables.
- Keep the setup minimal: no page objects, helpers, fixtures or extra dependencies until they are asked for.
- Failed runs keep traces and screenshots in `artifacts/`. A trace records typed values, including the password, so don't share those folders.
